### 2.1 下探一层

`tests/test_p0_propagation.py:61-67`：A15 = `not _miss and _fresh`；
其中 `_fresh` 来自 `os.system("python3 tools/manifest.py --fresh")`。

```
$ python3 tools/manifest.py --fresh
  翻转组_结构补齐_123批.md    ⛔表旧于工具 0.4 小时——须重跑，其数暂不可引用
```

`tools/manifest.py:399-401`：判据为 `os.path.getmtime(产出) < os.path.getmtime(工具)`。

```
$ stat -c '%y %n' tools/jiegou_buqi_123.py evidence/翻转组_结构补齐_123批.md
2026-09-13 10:44:16  tools/jiegou_buqi_123.py        ← 本批我改了它（撤 hu_via_editor）
2026-09-13 10:20:18  evidence/翻转组_结构补齐_123批.md
```

差 23.97 分钟 ＝ **0.4 小时**，与报文逐位吻合。

⇒ **耦合通道是文件系统 mtime，不是 import。**
`tests/test_p0_propagation.py` → `os.system` → `tools/manifest.py --fresh`
→ `getmtime(evidence/翻转组_结构补齐_123批.md)` vs `getmtime(tools/jiegou_buqi_123.py)`。

## 三、⭐⭐ 受控实验（四步，含**反向控制**）

⛔ 依上级令「**不靠反复跑绿来解释**」——本节**不是**重复跑，而是**操纵自变量后观察因变量**。

| 步 | 操作 | 预测 | 实测 | |
|---|---|---|---|---|
| 1 | 当前态（工具新于表） | FAIL / `exit=1` | **FAIL / `exit=1`** | ✅ |
| 2 | 重跑 `tools/jiegou_buqi_123.py` 生成表 | PASS / `exit=0` | **PASS / `exit=0`** | ✅ |
| 3 | ⭐ **只 `touch tools/jiegou_buqi_123.py`，不改一字** | FAIL / `exit=1` | **FAIL / `exit=1`** | ✅ |
| 4 | 再重跑表 | PASS / `exit=0` | **PASS / `exit=0`** | ✅ |

⭐⭐ **第 3 步是关键**：内容未变、语法完好、脚本可正常执行，**仅 mtime 改变**即复现失败。

⇒ 由此**排除**两个竞争假说：
- ⛔ **排除**「语法损坏本身致败」——步骤 3 语法完好而照样 FAIL；
- ⛔ **排除**「随机／环境抖动之 flaky test」——四步四中，且**可按需开关**。

⇒ **这不是 flaky test。这是设计如此的状态依赖**：
「**表须不旧于其工具**」是 `manifest.py` 的**既定纪律**（L390 自述），
凡改工具而未重跑表，A15 即红。**它正在按设计工作。**

## 四、⛔⛔ 本批自查：126K 那句理由是**推理错误**

126K 原文：

> 「⛔ 我**没有找到因果链**（**该测试不 import `jiegou_buqi_123`**）。」

⛔ **括号中的理由不成立，且是错的推理形态**：

| | |
|---|---|
| 我做的 | 查了**一种**耦合通道（`import` 图），得阴性 |
| 我断的 | **不存在**因果链 |
| 实情 | 耦合经由**文件系统 mtime**，`import` 图上本就看不见 |

⇒ 形态：**以某一检索面之阴性，断言全域之阴性。**
⭐ 这与已登记之 **B 类 `lexical_false_negative`**（只检索带标记词之规则，即闸门9⑦）**同构**，
亦与 **A2 `tool_output_truncation`**（证据链经未证完备之输出）同母型。

⇒ 登记为 **B 类之工程侧新实例 `B-ENG-01 dependency_graph_false_negative`**，
**状态 `proposed`**（⛔ 不自行新立故障类，待上级裁）。
⚠ 写入 `rules/failure_classes_v0.json` 之 `instances`，**不改 B 类定义本身**。

### 4.1 并一处方法论错误：**重复测量 ≠ 独立样本**

126K 我以「工作区与 HEAD **各跑 3 次皆 exit=0**」支持「无法复现」。

⛔ 那 6 次**全部落在「表已于修复过程中被重新生成」之后的同一状态点上**
（修语法 ⇒ 跑通工具 ⇒ 表 mtime 更新 ⇒ A15 转绿）。
⇒ 是**同一状态重复测量 6 次**，**不是 6 个独立样本**。

⭐ **对一个状态依赖的失败，跑 N 次绿不具证伪力**——N 再大也一样，因为自变量根本没动。
⇒ 上级令「**不靠反复跑绿来解释**」**在本例中被直接证实是对的**。

## 六、⭐ 由本例得之工程结论（⛔ 只登记，不外推为通则）

1. ⭐ **`tests/*.py` 之 exit code 对「工作区处于何种中间态」敏感。**
   ⇒ ⛔ **「测试全绿」不是一个状态无关的事实**，报账时须连同「**在哪个状态点上绿**」一并报。
2. ⭐ **凡改 `tools/` 下之产出工具，须于同批重跑其产出表**，否则 A15 必红。
   ⚠ 这是 `manifest.py` 的既定纪律在起作用，**不是缺陷**，⛔ 不得为让测试变绿而放宽该判据。
3. ⭐ **日后遇测试异常，第一步是读失败断言文本，不是重跑。**
   本例中，失败断言一读即指向 A15，再两跳即达 mtime；而重跑 6 次得到的是**错误结论**。
4. ⚠ **本例不推广为「所有瞬时失败皆为 mtime」**——仅此一例已证。
