# ASSERTION_TYPE_SPEC —— 断言类型最小规范（119批立·用户令一）

**立此规范之由**：118批 实测——117批 把若干硬断言改写为「候选触发」，
**但引擎没有 candidate/confirmed 类型系统，故那只是中文措辞，执行语义未变。**
⇒ **P0 修复未闭环。本规范即为闭环之第一步。**

⛔ **本规范只做「能保证执行语义不同」之最小约定。不发明 ontology，不做大型重构。**

---

## 一、机器可解析标记（唯一合法写法）

```
{{at:<type>|obj=<对象>|src=<原著锚>|scope=<适用域>}}
```

- **必须写在该判据行内**，紧跟被标注之判据。
- `at:` 之值只能取下节七种之一；**其余一律视为语法错误**，由 `tools/assertion_lint.py` 报红。
- `obj=` 作用对象（如 `苓桂术甘汤方证` / `太阳病` / `表位`）——**用户令：作用对象必须明确**。
- `src=` 原著锚（如 `讲伤寒·114815`）——**无锚者不得标 `confirmed`**。
- `scope=` 适用域（`D0`–`D5` 或具体条件，如 `§91·误下后续得`）。

**为何用 `{{at:...}}` 而非中文**：中文措辞无法机器解析，
118批 已实测「候选触发」四字在下游与 `沉=里` 走同一分支。**标记必须是字段，不能是形容词。**

---

## 二、七种类型及其语义

| 类型 | 含义 | 可做 | ⛔不可做 |
|---|---|---|---|
| `trigger_candidate` | 触发候选 | 生成候选／增补采问／提检索优先级／作组合证据之一 | **见第三节七禁** |
| `supporting_evidence` | 方向支持 | 提高某候选之后验；参与组合确认 | **不得单独确认；不得单独排除** |
| `confirmed` | 已确认 | 进入判词；参与排除；过方证门 | 须有 `src=` 锚；无锚不得标 |
| `exclusion` | 排除（反证） | 排除某候选 | ⛔**必须来自独立阳性证据**；`absence` 不构成 `exclusion` |
| `contraindication` | 禁忌 | 阻断治疗 | ⛔**禁忌 ≠ 诊断为假**：禁某方不等于否某证 |
| `unknown` | 未知 | 触发补采；悬挂 | ⛔**不得当 false；不得参与任何排除** |
| `disputed` | 有争议 | 并列呈现两说＋各自 provenance | ⛔**不得当 false；不得静默择一** |

### 六条不等式（本规范之核心，违者即语义未闭环）

```
trigger_candidate  != confirmed
unknown            != false
supporting_evidence!= confirmed
exclusion          != absence
contraindication   != diagnostic_false
disputed           != false
```

---

## 三、⛔ `trigger_candidate` 七禁（用户令锁死）

`trigger_candidate` **绝不能单独**：

1. 确认六经
2. 确认寒热虚实
3. 排除竞争证
4. 通过方证硬门
5. 触发治疗
6. 触发禁忌
7. 作为最终证型成立依据

**「单独」之定义**：该候选是其结论链上**唯一**的非 `unknown` 输入。
若另有 `confirmed` 或两个以上 `supporting_evidence` 共同支撑，则不受此禁。

## 四、观察状态（用户令四·与断言类型正交）

```
observation_state:
  present               明确记载「有 X」
  absent_explicit       明确记载「无 X／不 X」
  unknown_not_asked     问诊模式下未问
  unknown_not_recorded  回顾模式下未载
  uncertain             记载含糊或前后矛盾
```

| 状态 | 可作缺失证据？ | 可触发排除？ |
|---|---|---|
| `present` | — | — |
| `absent_explicit` | ✅**唯一可作** | ✅ |
| `unknown_not_asked` | ⛔ | ⛔ |
| `unknown_not_recorded` | ⛔ | ⛔ |
| `uncertain` | ⛔ | ⛔ |

⇒ ⛔ **只有 `absent_explicit` 才是「缺失证据」。其余四态皆不得触发排除。**
⇒ **`uncertain` 不得当 `absent`。**

## 五、类型在执行链各层之读法（用户令 1.2）

**每层必须对三者给出不同动作，不得走同一 Boolean 分支。**

| 层 | 读到 `trigger_candidate` | 读到 `confirmed` | 读到 `unknown` |
|---|---|---|---|
| 观察层 | 记为候选触发项，入候选池 | 记为事实 | 入补采清单 |
| 候选生成 | **生成候选**，权重 = 低 | 生成候选，权重 = 高 | 不生成，仅挂起 |
| 证据累计 | 累加为 partial | 累加为 full | **不累加**（不加不减） |
| 竞争排除 | ⛔**不得据以排除任何竞争证** | 可排除（须有独立阳性反证） | ⛔**不得据以排除** |
| 六经判定 | ⛔不得单独定经 | 可定经 | 悬挂，输出「六经未定」 |
| 寒热虚实 | ⛔不得单独定性 | 可定性 | 该轴标 `未定` |
| 方证入口 | 可提升检索优先级 | 可进入匹配 | 不影响 |
| **方证硬门** | ⛔**不得通过** | 可通过 | ⛔不得通过，转「止方·信息不足」 |
| 打分 | 低权重加分 | 高权重加分 | **0 分，且不扣分** |
| 禁忌 | ⛔不得触发禁忌 | 可触发 | ⛔不得触发 |
| 最终输出 | 只能出现在「候选／证据不足／需补采」栏 | 可出现在判词 | 出现在「待采清单」 |

## 六、参考实现与验收

- **参考解析器**：`tools/assertion_engine.py`——读引擎文本之 `{{at:}}` 标记，
  实现本规范之传播格，供 T1–T10 执行语义测试调用。
- ⛔⛔ **界限声明**：参考解析器测的是**本规范之实现**，
  **不是 LLM 读引擎时的实际行为**。后者在本工程现有条件下 **NOT_TESTABLE**。
  **不得把参考解析器通过写成「执行语义已验证」。**

### 验收（用户令十一）

`C2` 测试转绿之条件：引擎执行层出现**真类型标记** `{{at:...}}`，
且 `tools/assertion_engine.py` 能解析并使 T1–T10 全通过。
