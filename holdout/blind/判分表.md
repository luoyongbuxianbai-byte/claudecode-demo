## 流程

1. **一案一会话，或每会话 ≤5 案**（协议5·冷执行器纪律）。
2. 每会话：先贴引擎流通件全文 → 再贴**一案遮盲件** → 收 Schema。
3. **原样回传**，包括：拒绝作答、异常输出、格式不合——**这些都是数据，不要丢弃**。
4. 案号（B1-1…）**不要告诉执行会话它是第几例**，也不要提示族别。

## 判分口径（Code 侧揭盲时用，医师无需评分）

| 结果 | 记法 | 说明 |
|---|---|---|
| **CS** | 命中 | 引擎所出方与金标准同（含合方主方相同） |
| **CF** | 未中 | 出方但与金标准不同 |
| **止方·信息不足** | 止-I | 引擎判信息不足而止 |
| **止方·★库缺口** | 止-G | 引擎判★库无对应而止 |
| **止方·核心项未定** | 止-C | A4.9 第三分型 |
| **假止方** | FS | 金标准之方**在引擎库内且★可命中**，却判了止方＝漏诊 |
| **范围外** | OOS | 金标准为时方（非经方），引擎本不覆盖，**单列不计入分母** |

> **止方不算错**（除非是假止方）。这是本引擎的设计选择，判分须照此口径，
> 否则会把"诚实的不知道"记成失败。
