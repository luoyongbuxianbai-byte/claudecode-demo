# 开工五检 · 收工三件套（hxs-batch）

## 开工五检（闸门9⑭）

⛔⛔ **126AJ 改（上级实查所指）**：此处此前作「**任一项不过即停**」——
**没说【停什么】**。⇒ 一刀切会把「推送暂败」当成「原文不可靠」，也会诱人把失败**忽略掉**。

⭐ **现行：逐项写明【失败阻塞什么动作】，⛔ 也不许忽略。**

| 检查 | 失败 ⇒ **阻塞** | ⛔ **不阻塞** | ⛔ 不得做的事 |
|---|---|---|---|
| ① 语料 `--audit`（清洗降幅／协议16） | ⛔⛔ **一切以原文为据之断言**：取证、引锚、报数、挂条款 | 工具修复、文档整理、状态源修复 | ⛔ 不得「先读着，回头再核」 |
| ② 清单 `--check` 骤减 | ⛔⛔ **本批全部产出之提交** —— 资产可能已被误删 | — | ⛔ 不得 commit 绕过 |
| ③ TAIL（远端／本地不一致） | ⚠ **只阻塞 push 与「远端已是最新」之陈述** | ⛔ **不阻塞阅读与取证**——原文在本地语料里，与远端同步无关 | ⛔ 不得据此说「原文不可靠」 |
| ④ 冻结件 diff ≠ 0 | ⛔⛔ **一切提交** —— 冻结被破即须先查明 | — | ⛔ 不得 amend 掩盖 |
| ⑤ 产出新鲜度（普查册落后） | ⛔ **引用该册之任何数字** | ⛔ 不阻塞阅读 | ⛔ 不得引旧数 |

⚠ **凡阻塞被判为「不阻塞本批主体」者，须在报告 §未做里逐项写明**，
⛔ **不得静默通过**。⭐ 上级 126AJ 原话：「**同样，不能把失败忽略掉。**」

按顺序跑：

```bash
# ① 语料完备性与协议16（清洗降幅 >20% 即停；偏离冻结基线 >2% 即停）
python3 tools/corpus_guard.py --audit

# ② 资产清单核对（任一项骤减即可见）
python3 tools/manifest.py --check

# ③ TAIL：远端与本地是否一致（闸门9 第五款）
git fetch origin "$(git rev-parse --abbrev-ref HEAD)" && git status -sb | head -1
git log --oneline -1

# ④ 可达性：冻结件 diff 必须为空
#    ⚠ `git diff HEAD` 只证明**工作区相对 HEAD** 干净，
#      ⛔ 不证明【自 126 冻结基线至当前 HEAD】无变化 —— 后者须对基线 commit 取 diff：
git diff HEAD --stat -- V8/ runtime/ rules/core_v0.json
git diff 39fa549..HEAD --stat -- V8/ runtime/ rules/core_v0.json   # 39fa549 = 126批 冻结基线

# ⑤ 产出新鲜度：证据册是否落后于其生成器（闸门9⑮）
python3 tools/audit_population_census.py   # 重跑后 git diff 若有改动 ⇒ 上一批的册是旧的
```

⚠ ⑤ 常被跳过而它最容易出事：**引附录／证据册里的数之前，先确认那份册是这次跑出来的。**

### 并报一句现行相位

```bash
python3 -c "import json;d=json.load(open('rules/failure_classes_v0.json'));print(d['phase']['current']);print(d['phase']['order'])"
```

## 收工三件套（协议17）

### ① 报告

写 `reports/报告_第N批.md`。**首行报账**必含：

```
开工 HEAD `xxxxxxx`｜语料 12/12｜清单 --check 无减少｜测试 __/__｜冻结件 diff = 0
```

⛔⛔ **测试全绿不作为完成证明**（126批 令八）。
测试只能证明**已经编码进去的错误模型**没有违反自己；它不能证明**遗漏的语义条件**不存在。
⇒ 报告里必须另有一节，写**本批的实质证明是什么**（逐项锚文核对／逐条原文照录）。

报告必含的两节，缺一不可：

| 节 | 为什么不能省 |
|---|---|
| **未做** | ⛔⛔ **126AV 改（上级实查所指）**：此前要求「逐项列，不写其余」——**该要求与现行主要交付物冲突，已作废**。<br>⭐ **现行**：自 126AV 起，**主要交付物是 `reports/学术报告_胡希恕辨证论治体系重构_累计正文_v1.md`**，其 §八为**中央任务队列**。<br>⇒ **本节⛔ 不再逐项复列旧欠**：只写**本批新增、本批完成、本批改动优先级**这三类**增量**，其余**引用中央队列**（「其余见累计报告 §八，未变」）。<br>⛔ **仍不得写「其余」而不给指向**——指向中央队列，⛔ 不是省略。 |
| **我对本批的判断** | ⭐ **126AI 改（上级实查所指）**：此格此前要求「**含至少一条对自己的否定**」——⛔ **该配额已删**。<br>**配额会把反思变成填格式**：凑不出真错时就把「未做全书检索」之类的**已知限度**改写成「否定」，读起来像自查，实际上什么也没查。<br>⭐ **现行要求**（⛔ 不是数量）：**若本批发生了【已写下或已入库而后被改正】的判断，逐条写明：原文是什么、错在推理的哪一步、由谁发现（我方自查／上级／用户）、已传播到哪些现行引用。**<br>⛔ **没有发生，就写「本批未发现此类」，⛔ 不得用已知限度充数。**<br>⚠ **「没有发现」⛔ 不等于「没有发生」** —— 须同时写本批之**检出手段与其覆盖范围**（例：抽查了几分之几）。 |

### ② commit

⛔⛔ **收工提交顺序（126AI 立，⛔ 实测过 `--amend` 不收敛）**

⛔⛔ **126AJ 加一步（上级令三）**：**提交前先审查范围，⛔ 不默认 `git add -A`。**

```bash
# ⓪ 先看清将要提交什么 —— ⛔ 这一步不可跳
git status --porcelain
git diff --stat
#    逐条自问：这一项属于本批任务吗？若不属于 ⇒ 或另立提交，或 restore。
#    ⛔ 冻结件（V8/ runtime/ rules/core_v0.json）若出现在列表里 ⇒ **立即停**，先查明。

# ① 内容提交 —— ⭐ 显式列路径；⛔ `-A` 只在【已逐条看过 status】后才允许
git add <本批实际改动之路径…> && git commit -F - <<'EOF'
…（本批内容）
EOF

# ② 重跑交接包（此时 HEAD 已是内容提交）
python3 tools/handoff_pack.py

# ③ 第二次提交：交接包本身（⭐ 只加它）
git add docs/交接包_给上级线.md && git commit -m "126xx：交接包（由 handoff_pack.py 生成）"

# ④ push
git push -u origin <branch>
```

⚠ **为什么**：`-A` 会把**不属本任务的改动**（scratch 残留、工具试跑产物、他批未清件）
一并包进来，而**提交信息只描述本批** ⇒ **历史里出现无人认领的改动**。
⭐ 上级 126AJ 原话：「**批次提交不得默认 git add -A 包入不属本任务的改动，先审查范围。**」

⭐ **为什么不是 `--amend`**：amend 会**改哈希** ⇒ 交接包里写的 HEAD
**永远追不上它自己所在的那个提交**，改一次差一次。
⇒ ⭐ **两次提交才收敛**：交接包之 `HEAD` 指向**内容提交**，而交接包本身在**下一个**提交里。
⚠ **验收**：`grep '| HEAD |' docs/交接包_给上级线.md` 之值，须等于 `git rev-parse --short HEAD~1`。

---

⛔⛔ **126AV 删（上级实查所指）**：以下曾是一段独立的 `git add -A` 提交样例，
**与上文（§②「⛔ 不默认 `git add -A`，先显式列路径」）直接冲突** ——已确认为 126AJ 修订后的残留旧样例，删除。
⛔ **提交格式以上文 ①②③④ 四步为准，⛔ 无第二套写法。**

⛔ 「凡丢失后需重做之物，当批结束即 commit」（87批·用户令）——
工具、中间数据、摘录、映射表、检索式，全部入库，**不得只存 scratchpad**。
⚠ 本会话跑在可回收容器里：**没 commit 的东西，下一批就不存在。**

### ③ 送件

`SendUserFile` 送报告与本批主要产出。

#### ⛔⛔ ③-0　**回复里必须给出报告之【链接】**（126AL·上级令〇）

> **上级原话**：「工作报告没有停。我已核实远端 fe516a5，完整报告仍在 `reports/报告_第126AK批.md`。
> **只是聊天改成了摘要。以后应固定附报告链接，不能让你猜有没有交付。**」

⇒ ⭐ **聊天回复无论多短，末尾必须有这一行**（⛔ 不是可选，⛔ 不因「这批改动小」而省）：

```
报告：https://github.com/luoyongbuxianbai-byte/claudecode-demo/blob/<分支>/reports/报告_第N批.md
```

⭐ 取链接（⛔ 不手拼，避免分支名写错）：

```bash
printf 'https://github.com/luoyongbuxianbai-byte/claudecode-demo/blob/%s/reports/报告_第%s批.md\n' \
  "$(git rev-parse --abbrev-ref HEAD)" "<N>"
```

⛔⛔ **失效点**：⭐ **本步在【push 之后】才成立** —— 未推送之路径链接会 404。
⇒ **故 ③-0 之位置在 `git push` 之后**，⛔ 不得提前。

⚠ 同时更新 `docs/交接包_给上级线.md`：

```bash
python3 tools/handoff_pack.py
```

⇒ 跨线交接**由脚本生成，不由人转述**。转述会丢限定词，
而「C卷同族」硬化成断言、「63组」变成幽灵，都是这么来的。

## 收工前的三个自问

1. **我这批报出的每一个数，分母是怎么来的？**
   （`not_applicable`／无锚不进分母；`unknown` 不进分子；分母须由枚举产生）
2. **我这批有没有作过否定性断言？如果有，那次检索带截断参数了吗？**（A2）

## 研究单元之默认交付方式（126AA 上级裁决）

> 上级 126AA：三件套「**作为默认交付方式**。⚠ **文献缺口本身也可能是有效产出，
> ⛔ 不能强造竞争解释或检验结果。**」

每个研究单元默认产出**三件**：

| 件 | 要求 |
|---|---|
| **有限结论** | ⭐ **每条自带辖域**（限哪几段／是否做过枚举／是否报比率） |
| **竞争解释** | ⭐ 列出**本册不能排除**者，并各写「对它有利／不利」之材料 |
| **一项实际核证结果** | ⛔ **不是待办** —— 本批真的跑了、真的读了，写出结果（零命中也是结果） |

⛔⛔ **但不得强造**（126AA）：
⛔ 材料只够说明「**这里有一个文献缺口**」时，**就写缺口** ——
⛔ 不许为凑满三件而**编一个竞争解释**，⛔ 也不许**编一个检验结果**。
⭐ **缺口本身就是有效产出**，前提是它写明了**缺的是什么**（见 `hxs-gates` 末节三选一）。

## ⛔ 动态状态**不得手抄**（126X 立，126AA 收紧）

⛔ 断点、覆盖率、计数、逐书状态 ⇒ **一律由权威数据生成**（账本 → `reading_ledger.py` → `handoff_pack.py`）。
⭐ **126AA 补一条例外**：**报告可以保存【带提交版本的历史快照】** ——
　⭐ 即 `reports/报告_第N批.md` 里的数字**是那一批的快照**，标明 commit 即可，⛔ 不须随后续批次更新。
⛔ 但**台账与交接包**是**现行状态**，⛔ 不得存快照。

# ⛔⛔ 三项**写结论之前**的检查（126AG 上级令，⛔ 只此三项，⛔ 不另建体系）

> 上级 126AG：「**预防要放在生成结论之前，而不是继续增加复盘文字。**」
> ⭐ **自动检查负责提示，人负责语义裁决。**

## ① 写结论前，**对照自己的证据表**

⛔ 三条硬规则，逐条对照本册自己的表：

| 表里写的是 | ⛔ 结论里**不得**写成 |
|---|---|
| 「**未记**」「（未记）」「该段没写」 | 「**无**」「没有」「不存在」 ⇒ ⛔ **这是 RET-36／37 那一类** |
| 「**作者解释**」「作者释为」「作者判为」 | 「**已证明**」「原文支持」「文本依据」 |
| 表内**同时有两个以上因素在变**（如误治方式不同、条文来源不同） | 「**单因素比较**」「只差这一项」 |

⭐ **126AG 之实例**：`V-06` 把 §82「未记气上冲」填成「⛔无」，
再据以写「条文级能支持两证之别的只有……**之有无**」——
**表里是「未记」，结论写成了「无」。** 这一步**在表已经画好之后才发生**，
所以**对照表就能拦住**。

## ② 引用旧结论前，**先查版本与撤回状态**

```bash
python3 tools/prior_work.py --range <起> <止> --terms <方名> <术语>
```

⛔ 三条：
- ⛔ **命中之后必须去读原册**，⛔ 不得照抄其结论 —— **旧结论只用于定位**；
- ⛔ 输出标 `⚠ 该文件含撤回登记之 probe 字串` 者，**须先查该册哪一句被撤**；
- ⛔ **`FAILED` ⛔ 不得当作「没有旧账」**（工具以非零码退出）；`EMPTY` 只表示「按这些字面形态没查到」。

⭐ **研究册、摘要、报告须引用【同一个现行命题位置】**
（`rules/report_index_v0.json` 之条目 id）—— ⛔ **不靠每批手抄结论维持一致**。

## ③ 复核时，**同时查未展开的读记**

⛔ 每批收工前两件，缺一不可：

1. **本批每个重要结论，逐条回原文核**（⛔ 不是核自己的引文，是核**原文区间**）；
2. ⭐ **另选一个【未展开】的简记单元，独立复读一遍**
   —— 因为**只审长篇专题，会漏掉被简记隐藏的误读**。

⛔⛔ **该复读只提供【抽查结果】** ——
⛔ **不得**据以写「本批无遗漏」「未发现漏读 ⇒ 没有漏读」。
⭐ 上级 126AG 逐字：「**没有发现漏读，不等于已经证明没有漏读。**」

---

⭐ **这是防错机制，⛔ 不是错误不会再发生的保证。**
上级 126AG：「**任何模型都不能承诺零错误；能做的是减少错误产生，
并提高错误在进入报告前被发现的概率。**」
