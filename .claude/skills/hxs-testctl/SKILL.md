# 测试负控配对（hxs-testctl）

## 病史：同一个错，五次

| 批 | 错法 |
|---|---|
| 118 C2 ／ 119 A2·A15 ／ 120 T13c | 断言某字符串不在文件中 ⇒ **绿了，但是为错误的理由绿的** |
| 123 `test_pulse_cells` | 断言「`洪大=阳明气分` 不在 V8」——而该串此时**只剩在撤销说明里**，测的根本不是活格 |
| 124 | 测试断言**写得比命令本身更宽**，挡掉了一个合法的域内反例 |

前四次是同一形状：**绿色不证明命题成立，只证明「我查的那个东西不在我查的那个地方」。**
第五次是反向：**把一条禁令加严，和违反它一样是失准。**

⇒ 一条绿色测试的信息量，取决于**它在什么情况下会红**。
**说不出它何时会红的测试，是零信息。**

## 规程

### 每条断言，先写「它何时该红」

写断言之前，在注释里写一行：

```python
# 本断言之负控：<在什么档／什么输入下，它必须变红>
```

写不出来 ⇒ 这条断言不要写。

### 否定断言（「X 不存在」）必须配正控

否定断言最危险，因为**它在对象消失时也会绿**。配对方式：

```python
# 正控：改前档里必须找得到 X（否则说明我根本没在测这件事）
assert find(X, ARCHIVE_BEFORE), "正控失败：改前档也查不到 X ⇒ 检索式或对象搞错了"
# 负控：现行档里不得有 X
assert not find(X, CURRENT), "X 仍在现行档"
```

⚠ 123批 的教训更细一层：**「找得到」要找在正确的粒度上。**
那次 `洪大=阳明气分` 字符串还在（在撤销说明里），但**活格已经没了**。
⇒ 否定断言要**穿过解析器看活对象**，不要在原始文本上做字符串匹配。

### 整套测试必须有一个负控档

现行两个，是本工程测试可信度的实际来源：

```bash
python3 tests/test_cell_level_revocation.py --legacy      # 须红 5：行级污染
python3 tests/test_proposition_atomization.py --rebundle  # 须红 3：命题绑回去
```

⚠ **这两个脚本在负控档下退出码为 0**，因为「如期失败」即是通过。
读结果要看输出里的 `如期失败 N 项`，**不要只看退出码**。

新增一整套测试时，问：**把它要防的那个错误重新放回去，它会不会红？**
不会 ⇒ 这套测试没有测在它声称的那个点上。

## ⛔ 测试不作为完成证明

126批 令八，且这是本工程最重要的一条测试纪律：

> **测试只能证明【已经编码进去的错误模型】没有违反自己；
> 它不能证明【遗漏的语义条件】不存在。**

⇒ 报告里写「17/17 绿」是**报账**，不是**证明**。
实质证明只能是**逐项的锚文核对**。

⚠ 126D 亲手量过一次这个距离：在交付通读 skill 的同一小时里，
用一个 `head -10` 把自己截成了一个全称否定，而当时测试全绿。

## 与 A2 的联动

测试里凡有「扫全库确认无 X」这类断言，其扫描**不得带截断参数**：

```python
hits = [m for m in re.finditer(pat, text)]   # ✅ 全量
# hits = hits[:10]                            # ⛔ 截断后不得用于否定断言
```

## 自检四问

1. 这条断言**何时会红**？说不出 ⇒ 删掉。
2. 它有**正控**吗？（在改前档／回归样本上必须能找到目标）
3. 它测的是**活对象**还是**原始文本里的字符串**？
4. 它是不是**比它所依据的命令更严**？（124批 之错）
