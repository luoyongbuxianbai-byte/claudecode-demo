## 二、candidate/confirmed 类型系统实际落地

**规范**：`docs/ASSERTION_TYPE_SPEC.md`。机器可解析标记：

```
{{at:<type>|obj=<对象>|src=<原著锚>|scope=<适用域>}}
```

**七类**：`trigger_candidate`｜`supporting_evidence`｜`confirmed`｜`exclusion`｜`contraindication`｜`unknown`｜`disputed`

**六不等式全部实装并由测试断言**：

```
trigger_candidate != confirmed        supporting_evidence != confirmed
unknown           != false            exclusion           != absence
contraindication  != diagnostic_false disputed            != false
```

**引擎内已植入合式标记 22 处**（`trigger_candidate` 10｜`supporting_evidence` 7｜`confirmed` 3｜`disputed` 2），
语法与锚检查通过（**标 `confirmed` 而无 `src` 锚者：0**）。

**传播矩阵**（`term_layer/P0候选确认类型传播矩阵.md`）——十一层，
`trigger_candidate` 于【竞争排除／六经判定／寒热虚实／方证硬门／禁忌】五层皆为 `forbidden`，
即用户令七禁之所在。**三者不走同一 Boolean 分支，由 `LATTICE` 实装、由测试断言。**

⛔ **界限**：参考解析器 `tools/assertion_engine.py` 证的是**规范可解析**，
**不是 LLM 读引擎时照做**。后者见第九节。
